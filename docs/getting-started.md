# Getting started

For hosted use without installing Wattever, see [Browser mode](browser.md). The instructions below cover the full local helper.

Install Python 3.9 or newer. Wattever does not need Python packages or a JavaScript build. Choose a provider mode:

- **OpenAI-compatible endpoint:** start an inference engine such as Strata, llama.cpp or LM Studio and load your model there. Wattever needs streaming Chat Completions; model discovery is optional. Other OpenAI API surfaces are not required or implemented by this integration.
- **LM Studio (managed):** install [LM Studio](https://lmstudio.ai/), download models and run `lms bootstrap`. Wattever can load/unload models and schedule context and MTP settings through its CLI. The API defaults to `http://127.0.0.1:1234`; `LMS_BASE_URL` changes that managed connection. Explicit configured URLs and saved measurements keep their original addresses and timing provenance.

Download and extract the [Wattever 2.5.4 source archive](https://github.com/lpalbou/Wattever/releases/download/v2.5.4/Wattever-2.5.4.zip), or clone the repository. Use documentation matching that source version. Start `Wattever.bat` on Windows, `Wattever.command` on macOS, or `sh Wattever.sh` on Linux. You can also run `python -m wattever.server` in the extracted folder or repository. The server listens on loopback and prints its URL; keep its window open. `GPU_BENCH_PORT` sets the starting port (default 8713); `GPU_BENCH_NO_BROWSER=1` suppresses automatic browser opening.

On **Run**, choose your provider. For a generic endpoint, enter your engine's API base URL, such as `http://127.0.0.1:8000/v1` (a root URL also works), and optionally the name of an API-key environment variable. Set the variable before starting the helper; enter its name, never its secret value, in Wattever. Click **Connect**. Wattever supplies a display name and an opaque route identity automatically; no label or ID is required. Model discovery lists the IDs exposed by the connected endpoint. If the provider does not expose `/models`, supply its exact served model ID manually. The Python helper connects directly, so browser CORS permission is only needed in hosted browser mode.

Endpoint names come from recognized public cloud hosts or explicit service metadata when available. Local/private metadata probes are bounded, read-only requests; Wattever does not identify software from a port number or model name. If the software cannot be established, it uses an honest **Local endpoint**, **Private endpoint** or **Remote endpoint** fallback. An optional advanced **Display name** override is the only naming field you need to edit. Detected route location does not establish where inference runs; the local-inference confirmation remains a separate assertion.

Select models, prompt sizes, query counts and repeats. Configure quantization, context allocation, KV cache, placement and MTP in the external engine. **Requested reasoning** defaults to **None** in the UI and sends `reasoning_effort`; choose **Provider default** to omit it. Unsupported values fail visibly, and accepted requests do not verify effective behavior. Reproducibility fields and reported MTP/reasoning record operator knowledge; they do not change the engine. A canonical model ID can identify a checkpoint behind a served alias. To add or repair models inside an existing GPU benchmark, reconnect its endpoint and choose **Add / rerun tests** in Results. External model loading stays under the engine's control. LM Studio also supports automatic load/unload and separate-file resume.

With Strata Control, start the Strata server and load your chosen model in that application before connecting. Wattever does not start, switch or restore Strata models. Multiple detected GPUs do not establish that a model uses every card: supported placement, tensor parallelism and KV-cache modes depend on the serving engine and model architecture. Record the effective settings reported by the backend; a requested or accepted mode alone is not proof of its execution.

Hardware discovery describes the benchmark client. Leave **Inference runs on this computer** unchecked for remote or uncertain deployments. Checking it explicitly attributes local sensors to inference; it does not verify the server's hardware. Telemetry does not select execution placement. On supported NVIDIA systems, the helper records every detected card's power, utilization, VRAM, clocks and available temperature, together with combined GPU board power. Missing readings remain unavailable. Concurrent workloads use one group energy window, retaining per-card contributions without adding overlapping request energy. CPU/system estimates are separate from measured GPU power and do not replace a wall meter. Record placement and other relevant settings, and close competing workloads for comparisons. The macOS launcher offers optional authorization for `powermetrics`; throughput measurements work without it.

Use **Results** to select and compare benchmark files, download JSON, or copy tables. See [measurements](measurements.md) before comparing and [troubleshooting](troubleshooting.md) if setup fails. Return to [overview](../README.md); see [API](api.md) for integration.

Keep manufacturer/model/memory board annotations when comparing cards with the same GPU chip. Consolidation rejects conflicting known board identities or known variants while retaining compatibility with legacy unknown metadata; it preserves the original measurement rows and source evidence.

For controlled GPU transfer and placement experiments, see the [multi-GPU engineering study](dual-gpu-communication-and-placement.md). Its diagnostic captures, profiling overhead and study tools have separate protocols and requirements; they are not added to normal benchmark aggregates.

Use **Capabilities** for task accuracy after connecting in **Run**. Select a model, suite and question count, review the answer budget and timeout, then start. Full suites can be lengthy; subsets record their exact seeded selection. Capability tests and validated imports require the helper. The hosted site supports their shared result library/export/comparison. See [capability evaluation](capabilities.md).

After updating Python or UI files, restart the helper and reload its page to use the complete build. The launcher identifies builds with `/api/version` `build_id`, reuses the same build, and can replace an identified idle older build even when the release version is unchanged. Active speed or capability runs are preserved. Use the printed helper URL; its port is separate from your model server's port, and restarting Wattever does not require stopping the inference engine.

After a timeout or cancellation, the helper remains busy while outstanding request workers are alive. Its status explains that it is waiting; new speed and capability runs become available when those workers exit. An external server may still be computing after a client request ends, so check its state before restarting a comparison.
