# Getting started

For hosted use without installing Wattever, see [Browser mode](browser.md). The instructions below cover the full local helper.

Install Python 3.9 or newer. Wattever does not need Python packages or a JavaScript build. Choose a provider mode:

- **OpenAI-compatible endpoint:** start an inference engine such as Strata, llama.cpp or LM Studio and load your model there. Wattever needs streaming Chat Completions; model discovery is optional. Other OpenAI API surfaces are not required or implemented by this integration.
- **LM Studio (managed):** install [LM Studio](https://lmstudio.ai/), download models and run `lms bootstrap`. Wattever can load/unload models and schedule context and MTP settings through its CLI. The API defaults to `http://localhost:1234`; `LMS_BASE_URL` changes that managed connection.

Clone the repository for the generic endpoint helper features. The [v2.4.1 archive](https://github.com/lpalbou/Wattever/releases/tag/v2.4.1) remains available with that release's feature set. Start `Wattever.bat` on Windows, `Wattever.command` on macOS, or `sh Wattever.sh` on Linux. You can also run `python -m wattever.server` in the repository. The server listens on loopback and prints its URL; keep its window open. `GPU_BENCH_PORT` sets the starting port (default 8713); `GPU_BENCH_NO_BROWSER=1` suppresses automatic browser opening.

On **Run**, choose your provider. For a generic endpoint, enter your engine's API base URL, such as `http://127.0.0.1:8000/v1` (a root URL also works), and optionally the name of an API-key environment variable. Set the variable before starting the helper; enter its name, never its secret value, in Wattever. Click **Connect / discover models**. Wattever supplies a display name and an opaque route identity automatically; no label or ID is required. If the provider does not expose `/models`, supply its exact served model ID manually. The Python helper connects directly, so browser CORS permission is only needed in hosted browser mode.

Endpoint names come from recognized public cloud hosts or explicit service metadata when available. Local/private metadata probes are bounded, read-only requests; Wattever does not identify software from a port number or model name. If the software cannot be established, it uses an honest **Local endpoint**, **Private endpoint** or **Remote endpoint** fallback. An optional advanced **Display name** override is the only naming field you need to edit. Detected route location does not establish where inference runs; the local-inference confirmation remains a separate assertion.

Select models, prompt sizes, query counts and repeats. Configure quantization, context allocation, KV cache, placement and MTP in the external engine. **Requested reasoning** defaults to **None** in the UI and sends `reasoning_effort`; choose **Provider default** to omit it. Unsupported values fail visibly, and accepted requests do not verify effective behavior. Reproducibility fields and reported MTP/reasoning record operator knowledge; they do not change the engine. A canonical model ID can identify a checkpoint behind a served alias. To add or repair models inside an existing GPU benchmark, reconnect its endpoint and choose **Add / rerun tests** in Results. External model loading stays under the engine?s control. LM Studio also supports automatic load/unload and separate-file resume.

Hardware discovery describes the benchmark client. Leave **I confirm inference runs on this computer** unchecked for remote or uncertain deployments. Checking it explicitly attributes local sensors to inference; it does not verify the server's hardware. The GPU selector chooses a power sensor, not execution placement. Record placement and other relevant settings, and close competing workloads for comparisons. The macOS launcher offers optional authorization for `powermetrics`; throughput measurements work without it.

Use **Results** to select and compare benchmark files, download JSON, or copy tables. See [measurements](measurements.md) before comparing and [troubleshooting](troubleshooting.md) if setup fails. Return to [overview](../README.md); see [API](api.md) for integration.

Use **Capabilities** for task accuracy after connecting in **Run**. Select a model, suite and question count, review the answer budget and timeout, then start. Full suites can be lengthy; subsets record their exact seeded selection. Capability tests and validated imports require the helper. The hosted site supports their shared result library/export/comparison. See [capability evaluation](capabilities.md).

After updating Python or UI files, restart the helper and reload its page to use the complete build. The launcher identifies builds with `/api/version` `build_id`, reuses the same build, and can replace an identified idle older build even when the release version is unchanged. Active speed or capability runs are preserved. Use the printed helper URL; its port is separate from your model server's port, and restarting Wattever does not require stopping the inference engine.
