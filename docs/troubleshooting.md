# Troubleshooting

- **Hosted page cannot connect:** check the endpoint URL, server availability, CORS and your browser's local-network permission. HTTPS-to-localhost behavior varies by browser. See [browser mode](browser.md).
- **Browser storage warning:** download the result JSON before closing the page; an in-memory result is lost on reload.
- **Helper endpoint discovery fails:** verify the API base URL and optional key environment variable in the helper's process. Use a root URL or API base such as `/v1`, not `/chat/completions`. Enter the exact served model ID manually if `/models` is unavailable. Run a small case to verify streaming inference; CORS is not required for helper-to-engine requests. See [API configuration](api.md).
- **Endpoint name is generic or unexpected:** the service did not expose recognized metadata, or only route-origin information is available. A generic Local/Private/Remote endpoint name is valid and does not block inference. Connect again after correcting the URL, or set the optional advanced **Display name** override. No manual ID is needed. A regenerated ID after clearing local storage or removing the private registry is expected; keep URL mappings private.
- **Generic endpoint throughput is unavailable:** check whether the provider includes prompt and completion token usage in its stream. Wattever keeps throughput unavailable when those counts are missing; stream chunks are not tokens. Inspect `metric_sources` and `reported_timings` in JSON.
- **Generic power is unavailable:** local power attribution is disabled by default. Confirm inference runs on this computer before checking that assertion; a loopback proxy alone does not establish local inference. Remote server power cannot be measured by client sensors.
- **Generic endpoint context failure or timeout:** reduce the workload or adjust context/KV allocation in the inference engine. Inspect the engine after cancellation or timeout; client abort does not verify server termination. Reconnect and start a new run rather than resume/extend.
- **Helper timeout recovery stopped:** inspect LM Studio and ensure the model and requests have stopped before starting another run. See [measurements](measurements.md).

- **LM Studio or models unavailable:** install LM Studio, run `lms bootstrap`, start its server and check that the models are downloaded. Verify `LMS_BASE_URL` if using a different endpoint. Reopen Wattever and check the Run page.
- **Power unavailable:** check `nvidia-smi` for NVIDIA sensors. On macOS, use the launcher and accept the optional power prompt; without authorization speed tests still work. Other sensors may not provide power. See [measurements](measurements.md).
- **Load failure or context overflow:** reduce prompt size or simultaneous queries, inspect model context limits and available memory, or choose a smaller model. A failure is retained in results; use the retry option after correcting the cause.
- **Extension rejected:** extensions require managed LM Studio with matching hardware, selected GPU/driver, corpus and LM Studio version. Generic endpoints use new runs. Start a separate benchmark if compatibility changed or cannot be verified. See [sessions](measurements.md).
- **No response from Wattever:** check the URL printed by its launcher and keep the server window open. The default starting port is 8713 but another available port may be selected. See [getting started](getting-started.md).
- **Updated files but old UI or API:** finish active work, restart the helper and reload the page. `/api/version` includes a `build_id`; matching release numbers alone do not establish a matching build. The launcher preserves active speed/capability runs and can replace only an identified idle older helper. Use its printed URL; do not stop the model server to refresh Wattever.
- **Browser disconnect / WinError 10053:** a closed or aborted browser connection does not establish a benchmark failure. The helper handles disconnects while sending headers/body; reconnect and inspect saved status/results before starting another run. Update/restart an idle helper if its request handler still prints a disconnect traceback.
- **Capability parameter rejected:** select **Provider default** to omit unsupported `reasoning_effort`, or choose the token-limit field the endpoint supports. A changed request protocol is a distinct comparison. No visible answer after a short budget may mean hidden reasoning consumed it; inspect the run's usage/finish reason and adjust budgets fairly.
- **Capability import rejected:** use a finished full audit file with matching public configuration/suite/protocol/subset hashes and unchanged answers/grades. Redacted responses cannot be independently re-scored. Completed files need all planned observations; partial work uses cancelled/error/interrupted status. Do not repair hashes to conceal edited measurements.
- **CPU temperature unavailable or history starts late:** CPU temperature needs an actual supported sensor and can be unavailable while GPU temperature works. History retains the latest 3,600 points; check retention and all-run summary rather than interpreting absent samples as zero or no activity.

- **File-save warning:** review the warning's **Technical details** and retain downloaded JSON. For a managed LM Studio run, **Add / rerun tests → Add missing tests** can continue saved work after recovery. Generic endpoint runs start separately.
