# Troubleshooting

- **Hosted page cannot connect:** check the endpoint URL, server availability, CORS and your browser's local-network permission. HTTPS-to-localhost behavior varies by browser. See [browser mode](browser.md).
- **Browser storage warning:** download the result JSON before closing the page; an in-memory result is lost on reload.
- **A benchmark cannot be merged:** the merge dialog names the reason next to it. Benchmarks must come from one machine with the same GPU driver, corpus and protocol version, and must not be running. An endpoint benchmark saved as remote can join once you confirm that inference ran on the machine that launched it; one without a record of that machine cannot. Only one already merged benchmark can take part, and it stays the destination.
- **Helper endpoint discovery fails:** verify the API base URL and, if the endpoint requires one, the API key under **Connection options**. The key is never saved: enter it again after reloading the page or restarting the helper. Use a root URL or API base such as `/v1`, not `/chat/completions`. Enter the exact served model ID manually if `/models` is unavailable. Run a small case to verify streaming inference; CORS is not required for helper-to-engine requests. See [API configuration](api.md).
- **Endpoint name is generic or unexpected:** the service did not expose recognized metadata, or only route-origin information is available. A generic Local/Private/Remote endpoint name is valid and does not block inference. Connect again after correcting the URL, or set the optional advanced **Display name** override. No manual ID is needed. A regenerated ID after clearing local storage or removing the private registry is expected; keep URL mappings private.
- **Generic endpoint throughput is unavailable:** check whether the provider includes prompt and completion token usage in its stream. Wattever keeps throughput unavailable when those counts are missing; stream chunks are not tokens. Inspect `metric_sources` and `reported_timings` in JSON.
- **Generic power is unavailable:** local power attribution is disabled by default. Confirm inference runs on this computer before checking that assertion; a loopback proxy alone does not establish local inference. Remote server power cannot be measured by client sensors.
- **Generic endpoint context failure or timeout:** reduce the workload or adjust context/KV allocation in the inference engine. Inspect the engine after cancellation or timeout; client abort does not verify server termination. Once the engine is idle, reconnect and choose **Continue this benchmark…** or **Add / rerun tests**.
- **A model was skipped on an endpoint:** the endpoint answered but refused that model, for the test and for a short check sent afterwards. The failed test is recorded as `model_unavailable` with the endpoint's own message, the model's remaining tests are skipped, and the other models run normally. A typical cause is a served ID that is not a chat model, such as a speculative-decoding drafter. Fix or remove the model, then use **Retry failed tests**.
- **The benchmark stopped because the endpoint stopped responding:** after a failed request the helper waits up to a minute for the endpoint to answer again. If it does not, or if it rejects the API key, the run stops and the tests that did not run stay unrecorded. Restart the inference server, reconnect, and choose **Continue this benchmark…**.
- **A managed test is very slow, or LM Studio shows only part of the model on the GPU:** the model did not load at the requested placement and **Use CPU memory if needed** loaded it with fewer GPU layers. The result's **Placement** (`gpu_offload`) reads `auto`, `0.5` or `off` instead of `max`. Reduce the prompt size or query count so the context fits in VRAM, or turn the option off to record the load as a failure. See [automatic fallbacks and substitutions](measurements.md#automatic-fallbacks-and-substitutions).
- **Helper timeout recovery stopped:** inspect LM Studio and ensure the model and requests have stopped before starting another run. See [measurements](measurements.md).

- **LM Studio or models unavailable:** install LM Studio, run `lms bootstrap`, start its server and check that the models are downloaded. Verify `LMS_BASE_URL` if using a different endpoint. Then click **Connect** in Benchmarks; the Inference engine card says what it found.
- **Power unavailable:** check `nvidia-smi` for NVIDIA sensors. On macOS, use the launcher and accept the optional power prompt; without authorization speed tests still work. Other sensors may not provide power. See [measurements](measurements.md).
- **Load failure or context overflow:** reduce prompt size or simultaneous queries, inspect model context limits and available memory, or choose a smaller model. A failure is retained in results; use the retry option after correcting the cause.
- **Extension rejected:** extensions require matching hardware, selected GPU/driver and corpus. Managed LM Studio also checks its version; external repairs require reconnection to the saved endpoint. Start a separate benchmark if compatibility changed or cannot be verified. See [sessions](measurements.md).
- **No response from Wattever:** check the URL printed by its launcher and keep the server window open. The default starting port is 8713 but another available port may be selected. See [getting started](getting-started.md).
- **Updated files but old UI or API:** finish active work, restart the helper and reload the page. `/api/version` includes a `build_id`; matching release numbers alone do not establish a matching build. The launcher preserves active speed/capability runs and can replace only an identified idle older helper. Use its printed URL; do not stop the model server to refresh Wattever.
- **Browser disconnect / WinError 10053:** a closed or aborted browser connection does not establish a benchmark failure. The helper handles disconnects while sending headers/body; reconnect and inspect saved status/results before starting another run. Update/restart an idle helper if its request handler still prints a disconnect traceback.
- **Capability parameter rejected:** select **Provider default** to omit unsupported `reasoning_effort`, or choose the token-limit field the endpoint supports. A changed request protocol is a distinct comparison. No visible answer after a short budget may mean hidden reasoning consumed it; inspect the run's usage/finish reason and adjust budgets fairly.
- **Capability import rejected:** use a finished full audit file with matching public configuration/suite/protocol/subset hashes and unchanged answers/grades. Redacted responses cannot be independently re-scored. Completed files need all planned observations; partial work uses cancelled/error/interrupted status. Do not repair hashes to conceal edited measurements.
- **CPU temperature unavailable or history starts late:** CPU temperature needs an actual supported sensor and can be unavailable while GPU temperature works. On Windows, choose **Enable CPU temperature** in System and approve the administrator prompt; it installs the signed PawnIO driver and a read-only Wattever sensor task, and **Remove CPU sensor** undoes it. If the prompt was declined, nothing changed and the button stays available. Alternatively, start HWiNFO with Shared Memory Support enabled, or LibreHardwareMonitor with its remote web server on port 8085; the helper picks it up within seconds, without a restart. Wattever installs or elevates nothing unless you click the button. The System view states the reason a reading is missing. History retains the latest 3,600 points; check retention and all-run summary rather than interpreting absent samples as zero or no activity.

- **File-save warning:** review the warning's **Technical details** and retain downloaded JSON. For a managed LM Studio run, **Add / rerun tests → Add missing tests** can continue saved work after recovery. Generic endpoint runs start separately.
