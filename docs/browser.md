# Browser mode

Open [Wattever on GitHub Pages](https://lpalbou.github.io/Wattever/) to run a quick benchmark without installing Wattever. Start LM Studio or another OpenAI-compatible server with models available. Enter its endpoint (the default is `http://localhost:1234/v1`) and select **Connect**; Wattever does not request the model list until you connect. Choose models and workloads, start the benchmark, and keep the page open until it finishes.

The provider must permit cross-origin requests. LM Studio has an Enable CORS switch in its [server settings](https://lmstudio.ai/docs/developer/core/server/settings). Browsers may also require local-network permission, and HTTPS-to-localhost behavior depends on the browser and its security settings; see [Microsoft Edge local network access](https://learn.microsoft.com/en-us/deployedge/ms-edge-local-network-access). Wattever connects directly from the browser: it has no hosted proxy and does not use helper credentials. If the endpoint needs an API key, enter it in the page; the key stays in memory and the input clears after connecting. It is not saved in result files or browser storage.

Chrome versions with separate network permissions may call localhost access **Apps on device** or **Loopback network**. Allow the permission for the Wattever site when you connect. The permission is distinct from access to other devices on your LAN; see [Chrome local network guidance](https://github.com/GoogleChrome/modern-web-guidance/blob/main/skills/modern-web-guidance/guides/security/local-network-access.md).

GPU, CPU, RAM and VRAM fields are optional user-supplied descriptions, not hardware discovery. Browser mode cannot measure GPU power or VRAM use, load or unload models, choose model placement, allocate context, control MTP or reasoning, resume a session, or add and rerun cases in the same file. The provider manages those settings; configure it separately. Use the [full local helper](getting-started.md) when those controls and telemetry are needed.

Browser results record `measurement_mode: browser`, `browser_schema_version: 1` and protocol `browser-1`, with the bundled corpus identity and a SHA-256 hash when available. Timing occurs in the client; it includes network and browser overhead and is not directly comparable to helper protocol measurements. Prompt throughput is unavailable when the provider does not report exact prompt usage. Output token counts and throughput are marked estimated when completion usage is unavailable. A failed request is recorded as a failure, not zero throughput.

Results are stored in browser storage and can be downloaded or imported as JSON. Storage can be cleared or unavailable; if a storage warning appears, download the in-memory results before closing the page. Closing or reloading the page stops the browser benchmark, and a previously running result is shown as interrupted. On timeout the browser aborts its requests and stops the run, but cannot verify that the provider stopped inference or unload its model. Check the provider before starting another workload. Helper benchmarks instead continue in the local server when the page closes; see [measurements and sessions](measurements.md).
